# PKX110_16.0.10.500(CN01) LOS 디바이스 트리 업데이트 기록

작성일: 2026-10-07 (Asia/Seoul). 소스 통합·커밋 완료, 전체 ROM 빌드와 실기 검증은 미완료다.

세 저장소의 시작 작업 트리는 모두 깨끗했다. 참고/OEM 저장소는 읽기만 했으며, 대상 브랜치에 새 커밋을 추가했다. push·amend·reset·stash·기존 이력 재작성은 하지 않았다. 사용자 지시가 커밋을 명시했으므로 기존 CODEX-PROMPT의 자동 커밋 금지 예시보다 이번 요청을 우선했다.

제공된 문서의 “OEM HEAD는 .9.400”이라는 과거 설명과 달리 실제 로컬 HEAD는 .10.500이었다. 원격 최신을 추정하거나 fetch하지 않고, 제공된 로컬 원본의 위 전체 SHA로 고정했다.

**LOS 시작점에는 .200 import가 없었다.** 따라서 .200→.500만 적용하면 .200에서 추가한 충전·카메라·패널 변경이 빠진다. 이번 작업은 아래 두 단계를 합친 하나의 소스 업데이트다.

1. 실제 참고 저장소의 `22827657` 부모→커밋을 분석하여 .200 변경을 LOS에 보충한다.
2. OEM `183af72`→`6a196f79`의 변경을 그 결과에 적용한다.

최초 참고 `c9dca9dc`의 부모는 `ebb25e35`, 실제 로컬 참고 `22827657`의 부모는 `a52fefee`다. 둘은 동일 트리가 아니다. 후자에는 Piloti/Pista 소스와 Hummer AA590 partial-update 수정 등이 이미 있으므로 최신 로컬 참고본을 사용했다. LOS와 `a52fefee`의 차이는 kera/parrot/pineapple/ravelin의 mem-offline 삭제였다. 적용 후보의 부모 내용과 LOS 시작 내용을 개별 대조하여 충돌이 없음을 확인했다.

## 2. 결과와 반영 방식

소스 커밋: **81개 파일, 기존 48개 수정·33개 추가, 14,816줄 추가·3,990줄 삭제**. 삭제/이름 변경 및 기존 Git 모드 변경은 없다. 신규 파일은 0644다.

- .200 참고 import의 110개 경로 중 실질 수정 44개와 신규 28개를 반영했다.
- 형식/EOF/권한만 바뀐 37개는 현재 내용을 유지했다. 과거 c9 검토의 “33+5” 수치를 이 커밋에 재사용하지 않았다.
- `oplus/platform_map.bzl`의 Volkswagen 목록 추가 1건은 제외했다.
- .200→.500 OEM DT 변경은 16개(기존 13개, 신규 3개)다. 일부가 .200 보충 파일과 겹치므로 총계를 단순 합산하면 안 된다.
- 참조 누락을 해결하기 위해 Qualcomm의 Volkswagen 전용 파일 2개를 추가했다.

기존 파일의 모드·내용을 먼저 비교하고, 실질 변경이 없는 파일은 그대로 두었다. 실제 가져온 파일은 LF로 기록했다. 새로 추가/수정한 줄의 trailing whitespace와 space-before-tab만 정리했다. 기존 파일 전체의 공백 정리나 전체 chmod는 하지 않았다. 파일 시스템의 그룹 쓰기 권한과 Git의 100644/100755 모드는 구분해서 검사했다.

전체 파일별 처리와 최종 SHA-256은 [FILES.tsv](FILES.tsv)에 있다. `M`/`A`는 이번 소스 커밋 반영, `retain-format-or-mode`는 원래 내용 보존, `defer-vw-build-registration`은 의도적 보류다.

## 3. OEM 대비 일치·예외 확인

비교에서는 CRLF/LF, 줄 앞뒤 공백, EOF 차이를 분리했다. 다음 “일치”는 그러한 서식 차이를 제외한 내용 비교이며 원본과 바이트 동일하다는 뜻은 아니다. 변경 파일의 최종 해시는 별도 기록했다.

| OEM 범위 | 확인 결과 |
|---|---|
| oplus 전체 120개 | 117개 일치; Makefile/platform_map/공통 ADSP 파일 3개 의도적 차이 |
| audio/oplus 19개 | 모두 일치 |
| camera/oplus 25개 | 모두 일치 |
| display/oplus 43개 | 42개 일치; AA590 partial-update 예외 유지 |
| generic OEM 패널 7개 | 모두 일치 |
| wlan/oplus 10개 | 8개 일치; Hummer/Pagani XO trim 예외. Dodge 예외는 OEM에도 존재 |
| generic sun 파일 4개 | debug/pcie/pmic-overlay 일치; sun.dtsi는 아래 로컬 변경 유지 |
| 추가 Qualcomm 의존성 2개 | NEW_OEM에서 추가, 서식 외 원본 내용 유지 |

OEM 범위에 없는 Piloti/Pista 등 custom 전용 파일을 삭제하지 않았다. “OEM에 없으니 삭제”는 하지 않았으며, `oplus/`와 generic 파일을 전체 교체하지 않았다.

### 보존한 로컬 정책

- Dodge/Hummer/Pagani `&wlan_peach`: `nvmem-cells = <0>`, `nvmem-cell-names = ""`, `wcal-pbs-supply = <0>`. 세 파일 모두 시작점과 바이트 동일하다. `022598bf…`의 목적을 보존하며 옛 wlan_direct_link 정책을 함께 복원하지 않았다.
- `oplus/sun_overlay_common.dtsi`: `&adspslpi_mem`의 `<0x0 0x9ee00000 0x0 0x5080000>` 유지. 파일 자체가 시작점과 동일하며 기기별 중복 정의를 추가하지 않았다. 이번 OEM DT delta에는 이 메모리 맵 변경이 없다.
- `qcom/sun.dtsi`: UFS PHY의 `RPMH_CXO_CLK` 및 전용 symbol 연결, `qcom,dmof`, `restrict_cma_redirect=false`, ADSP를 공통 overlay에서 조정하는 구조 보존. 시작점 대비 변경은 enforce-high-irq-cpus 1줄 삭제뿐이다.
- Hummer AA590: `a52fefee`의 partial-update/ROI 비활성화 보존. 네 timing의 주석 처리를 OEM 값으로 되돌리지 않았다.
- LOS PASR: `450710a3`의 kera/parrot/pineapple/ravelin mem-offline 삭제 보존. 네 파일은 시작점과 동일하다.
- Piloti/Pista 소스와 선택 조건, qcom/Makefile 및 하위 Kbuild, 카메라 sun.mk 모두 유지했다.

소스에서 예외를 유지했다는 검사와 실제 부팅 DT 최종값 검증은 다르다. 아래 환경 제한 때문에 이번에 후자를 완료했다고 기록하지 않는다.

## 4. 빌드 등록 판단

새 Pagani MM 파일은 기존 24821/24875 최상위 overlay가 include하므로 별도 DTBO 등록이 필요 없다. 기존 Pagani 보드 두 개와 기존 audio/display/camera/WLAN 산출물 이름은 그대로다.

`oplus/Makefile`, `qcom/Makefile`, 모든 하위 Kbuild, `qcom/camera/config/sun.mk`, `oplus/platform_map.bzl`은 시작점과 바이트 동일하다. Volkswagen의 platform_map 네 항목만 추가하면 Makefile/Kbuild/카메라 등록과 일관된 지원이 되지 않으므로 제외했다. 향후 Volkswagen 지원 작업에서 DTB/DTBO 조합·선택 조건·패키징을 함께 처리해야 한다.

## 5. 드라이버 의존성 검토

동일 OEM SHA의 코드에서 FRR 소비 경로는 `vendor/oplus/kernel/mm/mm_osvelte/mm-config.h`와 `mm-config.c`의 `parse_frr_dt()`다. 여기서 `oplus_bsp_frr`의 `feature-enable`을 읽는다. 새 charging ID의 소비 경로도 `vendor/oplus/kernel/charger/v2/config/ic/buck_boost.json`, `hal/oplus_virtual_buck.c`, `charger_ic/oplus_hal_adsp.c`, `hal/oplus_virtual_rx.c` 등에서 확인했다.

이는 **해당 OEM 릴리스에 소비 코드가 존재한다**는 확인이다. 사용 중인 LOS 커널/모듈 저장소와 정확한 펌웨어 조합은 주어지지 않았으므로 런타임 호환성을 검증한 것이 아니다. .200→.500 전체 OEM 파일 목록에는 다수의 charger/mm/display/WLAN 드라이버 변경도 있으나 이 디바이스 트리 저장소에 복사하지 않았다. 실제 ROM 통합 시 특히 새 충전 정책·IC ID와 FRR의 소비 코드 버전을 점검해야 한다.

독립 검사는 `/dts-v1/; /plugin/;` wrapper에 실제 DTSI를 include하고 GCC cpp 13.3.0과 시스템 DTC 1.7.0의 `dtc -@`로 컴파일했다. 일반 GPIO/IRQ 매크로만 설치된 Linux 6.8 헤더에서 읽었고, 숫자 상수를 임의로 만들어 넣거나 DTC `-f`로 오류를 강제 통과시키지 않았다. 외부 phandle과 실제 부모 문맥이 없는 fragment이므로 경고가 있고, 이것은 ROM DTBO 빌드나 최종 조합 검증의 대체가 아니다.

실제 실패 근거:

```text
make -f Makefile dtbs
make: *** No rule to make target 'dtbs'. Stop.

cpp ... oplus/pagani-24821-sun-overlay.dts
fatal error: dt-bindings/oplus/hw-id.h: No such file or directory

Pagani 24821/24875 charging fragment
line 63: PMIH010X_ADC5_GEN4_AMUX1_GPIO6_100K_PU 등
상위 PMIC include에서 공급되는 상수가 없어 DTC 파싱 불가
```

두 충전 fragment 실패는 실제 Pagani overlay가 공급할 PMIC 헤더가 없는 독립 검사 환경의 제한이다. 그렇다고 완전한 ROM 빌드가 통과할 것으로 확정하지는 않는다. 실행 결과와 검증 목록은 [VALIDATION.json](VALIDATION.json)에 저장했다.

## 7. 다음 작업으로 넘기는 항목

1. 다음 OEM delta 기준은 선택 통합 범위에 한해 `6a196f79f77acd55cf302e1696c038e4cad99254`다. generic QCOM 전체나 모듈까지 동기화됐다는 뜻이 아니다.
2. Volkswagen build/packaging enablement는 의도적 보류다. OEM에서 다음번 변경이 없더라도 이 미처리 목록을 계속 검토한다.
3. generic Qualcomm/display의 현재 로컬 차이와 Piloti/Pista 혼합 출처를 유지한다. 원본 일치만을 위해 제거하지 않는다.
4. 실제 ROM 커널·모듈·dt-bindings·툴체인과 제품 설정으로 DTB/DTBO를 빌드하고, 실제 적용 순서대로 base+overlay를 조합한다.
